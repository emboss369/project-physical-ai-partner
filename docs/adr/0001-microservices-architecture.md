# ADR 0001: マイクロサービス化と NATS ベースのイベント通信を採用する

- Status: Accepted
- Date: 2026-08-11

## Context

Project Physical AI Partner は、音声入力から対話生成、TTS、アバター制御までを含む複雑なシステムを目指す。\nまた、GPU メモリ制約のある環境において、LLM / TTS / ASR を独立して再配置・再起動できる構造が必要である。

## Decision

以下の方針を採用する。

- 全体を 10 ほどのサービスに分割する
- 各サービスは独立したプロセスとして実装する
- サービス間通信は REST ではなく NATS を用いたイベント駆動にする
- GPU を必要なサービスへ局所的に割り当てる
- サービス間でデータベースを直接共有しない

## Consequences

### Positive

- 各サービスの再起動・更新が容易になる
- GPU リソースの制約に合わせて構成変更しやすい
- 将来の分散配置や機械追加に対応しやすい
- サービス境界が明確になり、保守性が向上する

### Negative

- 初期実装コストが増える
- サービス間の監視・トレーシング設計が必要になる
- イベントスキーマの管理が重要になる
